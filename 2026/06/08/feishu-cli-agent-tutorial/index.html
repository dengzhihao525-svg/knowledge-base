1. 飞书 CLI 是什么？

飞书 CLI 是飞书官方提供的命令行工具，可以通过终端操作飞书开放平台能力。

你可以把它理解成：

飞书开放平台 API 的命令行封装。

它可以操作很多飞书资源，例如：

  • 消息 / 群聊；
  • 通讯录；
  • 多维表格；
  • 飞书文档；
  • 云空间文件；
  • 日历 / 日程；
  • 表格 Sheets；
  • Wiki；
  • 任务；
  • 会议等。

  • Agent 负责理解任务、拆解步骤、判断需要哪个能力；
  • 飞书 CLI 负责真正调用飞书 API；
  • 飞书开放平台负责权限、数据和执行。

11. 日历权限：读取日历和创建日程不是一回事

这里非常容易踩坑。

飞书里“日历”和“日程”不是同一个概念：

  • Calendar：日历容器；
  • Event：日程 / 会议。

对应权限也不同：

能力 Scope
读取日历容器 calendar:calendar:readonly
创建日历容器 calendar:calendar:create
读取日程详情 calendar:calendar.event:read
查询忙闲时间 calendar:calendar.free_busy:read
创建日程 calendar:calendar.event:create
修改日程 calendar:calendar.event:update

这也是为什么“我已经授权日历了，为什么还不能创建日程”的原因。

因为读取日历和创建日程是两套 scope。

特别是创建日程：

它虽然是以当前用户身份创建，但可能会：

  • 占用你的日历时间；
  • 邀请别人参加会议；
  • 发送日程通知；
  • 创建飞书视频会议；
  • 影响其他人的工作安排。

所以这个权限很可能需要管理员审批。

16. 常见问题

Q1：为什么安装了 CLI，但还是不能操作飞书？

因为安装 CLI 只是第一步，还需要：

  1. 配置飞书应用；
  2. 在开放平台开启对应 API 权限；
  3. 用户完成授权；
  4. 目标资源本身允许访问。

Q2：为什么 Bot 能发消息，但不能访问我的文档？

因为 Bot 身份不是你本人。

Bot 可以作为应用机器人发消息，但它默认不能访问你的个人云空间、个人日历、个人文档。

Q3：为什么创建日程权限需要审批？

因为创建日程是写入操作。

它可能会：

  • 邀请别人；
  • 发送通知；
  • 占用日历；
  • 创建视频会议。

所以飞书会把它视为比较敏感的权限。

17. 总结

飞书 CLI 是搭建办公自动化 Agent 的一个非常好的入口。

它的价值在于：

  • 把飞书开放平台 API 封装成命令行；
  • 可以被 AI Agent 直接调用；
  • 能覆盖消息、日历、多维表格、文档、云空间等常见办公场景；
  • 支持 User / Bot 两种身份；
  • 支持最小权限逐步授权。

  • 自动管理任务和项目数据。

如果你正在学习 AI Agent，飞书 CLI 非常适合作为第一个真实办公场景练手项目。
