CC Switch 完整入门教程：一键切换 Claude Code 的模型供应商

一句话介绍

CC Switch 是一个专门给 AI 编程工具使用的桌面配置管理器。

它可以统一管理 Claude Code、Codex、Gemini CLI、OpenCode、OpenClaw 等工具的模型供应商配置，让你不用手动改配置文件，就能在不同 API、不同模型、不同 Key 之间快速切换。

如果你现在正在用 Claude Code，又想接入 DeepSeek、Kimi、通义、智谱、OpenRouter 或其他第三方 API，那么 CC Switch 基本就是一个必备工具。

官方项目地址：

https://github.com/farion1231/cc-switch

官方站点：

https://ccswitch.io

为什么需要 CC Switch

没有 CC Switch 的时候，切换 Claude Code 模型供应商通常要手动修改配置文件。

你可能需要自己处理这些内容：

  • API Key
  • Base URL
  • 模型名称
  • API 格式
  • MCP 配置
  • Skills 配置
  • 多个 CLI 工具各自不同的配置格式

这件事最麻烦的地方不是难，而是容易乱。

比如今天用官方 Claude，明天想换 DeepSeek，后天又想切到 Kimi。每切一次都要找配置文件、改字段、保存、重启、测试。如果手误写错一个字符，整个 Claude Code 就可能请求失败。

CC Switch 的作用，就是把这些配置都放到一个图形界面里。你只需要添加供应商，然后点击启用。

CC Switch 主界面

下面是官方 README 里的主界面截图：

在主界面里，你可以看到已经添加的供应商配置。每一个供应商都可以单独启用、编辑、删除，也可以通过系统托盘快速切换。

对 Claude Code 用户来说，最舒服的一点是：Claude Code 通常支持热切换。也就是说，你在 CC Switch 里切换供应商后，很多情况下不用重启终端就能继续使用。

CC Switch 能做什么

CC Switch 的核心能力可以分成几类。

第一，管理模型供应商。

你可以添加多个 Provider，例如官方 Anthropic、DeepSeek、Kimi、通义、智谱、OpenRouter 或其他中转服务。每个 Provider 都可以保存自己的 API Key、Base URL 和模型配置。

第二，一键切换。

添加好多个供应商后，只需要点击 Enable，当前工具就会切换到对应配置。Claude Code 通常可以直接生效，Codex、Gemini CLI 等工具一般建议重启终端后再使用。

第三，统一管理多个 AI CLI 工具。

它不只服务 Claude Code，也支持 Codex、Gemini CLI、OpenCode、OpenClaw 等工具。你可以在一个界面里管理多个工具的配置。

第四，管理 MCP、Prompts、Skills。

如果你已经开始使用 Claude Code 的 MCP 或 Skills，CC Switch 也能帮你做可视化管理，减少手动复制和同步配置的麻烦。

安装 CC Switch

最推荐的安装方式是从官方 GitHub Releases 下载：

https://github.com/farion1231/cc-switch/releases

Windows 用户下载 .msi 安装包即可。

macOS 用户可以下载 .dmg 文件，也可以使用 Homebrew：

Linux 用户可以根据自己的系统选择 .deb、.rpm 或 .AppImage。

安装完成后，打开 CC Switch。首次启动时，它会自动检测你本机已经安装的 AI CLI 工具，比如 Claude Code、Codex 或 Gemini CLI。

添加第一个供应商

打开 CC Switch 后，先在顶部选择你要管理的工具。这里以 Claude Code 为例，选择 Claude。

然后点击右上角的 + 按钮，进入添加供应商页面。

官方添加供应商界面如下：

添加供应商一般有两种方式。

方式一：使用预设供应商

这是最适合新手的方式。

CC Switch 内置了不少常见供应商模板。你只需要在预设列表里选择对应供应商，然后填写自己的 API Key。

大致流程是：

  1. 点击右上角 +
  2. 在预设列表里选择供应商
  3. 填写 API Key
  4. 检查模型名称
  5. 点击添加或保存

预设的好处是 Base URL、API 格式等信息通常已经帮你填好了，不需要自己猜。

方式二：自定义供应商

如果你使用的是第三方中转服务，或者预设里没有你的服务商，就选择自定义配置。

自定义配置通常需要填写这些内容：

  • 名称：自己能看懂就行，比如 DeepSeek-V4、Kimi-Claude、OpenRouter
  • API Key：从服务商控制台复制
  • Base URL：服务商提供的 API 地址
  • 模型名：你要使用的模型 ID
  • API 格式：根据服务商要求选择 Anthropic 或 OpenAI 兼容格式

这里有一个很常见的坑：Base URL 末尾不要随手加 /。

启用供应商

供应商添加完成后，回到主界面。

找到刚刚添加的 Provider，点击右侧的 Enable 或「启用」按钮。

如果状态变成 Active，说明当前工具已经切换到这个供应商。

你也可以在系统托盘里快速切换。Windows 一般在右下角，macOS 一般在顶部菜单栏。点击 CC Switch 图标后，选择对应供应商即可。

常见问题排查

API Key 错误

如果提示认证失败，优先检查 API Key。

确认你复制的是完整 Key，没有多余空格，也没有把别的平台 Key 填到当前供应商里。

Base URL 写错

如果提示连接失败，重点检查 Base URL。

常见问题包括：

  • 地址写错
  • 末尾多了 /
  • 服务商要求特定路径但你没填
  • 当前网络无法访问该服务商

模型名不支持

有些中转服务虽然兼容 Claude Code，但不一定支持所有模型名。

如果模型名写错，可能会出现模型不存在、400 错误或请求失败。建议先用服务商文档里的推荐模型测试。

API 格式不匹配

不同供应商可能支持不同 API 格式。有的支持 Anthropic Messages，有的支持 OpenAI Chat Completions，有的只是做了兼容转换。

如果一直报错，可以尝试切换 API 格式，或者换一个该供应商明确支持 Claude Code 的模型。

Claude Code 出现 400 错误

新版 Claude Code 有时会发送某些第三方服务不兼容的参数，比如 thinking 相关参数。遇到 API Error: 400 时，可以尝试：

  • 换成 Sonnet 或 Haiku 类模型
  • 换一个供应商
  • 查看 CC Switch 官方 GitHub Discussions
  • 确认第三方 API 是否明确支持 Claude Code

进阶功能

当你把添加供应商和切换供应商跑通以后，可以继续研究 CC Switch 的进阶功能。

MCP 管理

MCP 可以让 Claude Code 连接外部工具，比如文件系统、数据库、浏览器、GitHub 等。

CC Switch 提供了 MCP 管理入口，可以用图形界面添加、编辑和同步 MCP Server，减少手动改配置的麻烦。

Skills 管理

Claude Code 的 Skills 可以理解为给 Agent 增加特定能力包。

如果你经常安装、同步、管理不同 Skills，CC Switch 的 Skills 面板会更方便。

Prompts 管理

Prompts 功能适合保存一些常用提示词，比如代码审查、需求分析、Bug 排查、文档生成等。

你可以把常用 Prompt 做成预设，减少重复输入。

推荐学习顺序

如果你是第一次接触 CC Switch，不建议一上来就研究所有功能。

更推荐按这个顺序：

  1. 安装 CC Switch
  2. 添加一个供应商
  3. 启用供应商
  4. 在 Claude Code 里测试
  5. 再添加第二个供应商
  6. 学会在多个供应商之间切换
  7. 最后再研究 MCP、Skills、Prompts

先把最小闭环跑通，再慢慢扩展。

总结

CC Switch 解决的是一个非常实际的问题：AI 编程工具越来越多，模型供应商也越来越多，如果每个工具都手动维护配置，很快就会混乱。

它把 Claude Code、Codex、Gemini CLI 等工具的 Provider、API Key、Base URL、MCP、Skills 统一放到一个桌面界面里，让切换模型变成一次点击。

对于 Claude Code 用户来说，它尤其适合这几类场景：

  • 想接入第三方 API
  • 想降低模型使用成本
  • 想在多个模型之间来回切换
  • 想统一管理 MCP 和 Skills
  • 不想手动改配置文件

最后提醒一句：API Key 一定不要发到群里、截图里或公开文章里。如果不小心泄露，建议立刻去对应平台重置。
